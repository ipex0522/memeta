# Memeta

Salesforce 組織のメタデータを `sf` CLI 経由で取得し、組織ごとに世代バックアップする Windows/macOS/Linux 向けの Python 3 + Tkinter GUI ツールです。

第1版: **v1.0.0**（2026-09-22）。変更・検証内容は [CHANGELOG.md](CHANGELOG.md) を参照してください。

## 前提条件

- Python 3.10 以降（Tkinter を含む標準配布）
- Salesforce CLI (`sf`) が PATH 上にあり、対象組織へログインできること

追加の Python パッケージは不要です。

## 起動

Windows では `run.bat` をダブルクリックして起動できます。

```bash
python main.py
```

1. **設定・接続環境の管理**でエイリアス、ログイン URL、API バージョン、対象／除外タイプを登録します。
2. **package.xml 作成**で対象組織のメタデータタイプを取得し、必要なタイプを調整して manifest を保存します。
3. **メタデータ取得**で package.xml を持つ組織を選び、取得結果を `data/<org>/metadata/<日時>_<org>/` にバックアップします。

OAuth 認証では、設定画面の「新規環境としてログイン認証を実行」を押すと、Salesforce CLI が既定ブラウザを自動で開きます。認証が成功した組織だけが設定へ保存されます。設定ファイルの書式は `memeta_config.example.json` を参照してください。

### Salesforce CLI 互換性検査

組織の Metadata API が返す型の一部は、Salesforce CLI が source 形式へ変換できない場合があります。Memeta は `sf org list metadata-types --filter-known` で実行中の CLI レジストリに未登録の型を検出し、一覧から除外して表示します。手入力、既存の manifest、手編集済みの `package.xml` も、作成時と Retrieve 直前に検査します。検査できない場合は安全のため取得を開始しません。

### 取得時間の計測と SourceMember 追跡

各取得のフェーズ別ログを `data/<org>/logs/` に保存します。互換性検査、CLI 起動・終了、最初の CLI 出力、バックアップ、temp 清掃の所要時間と、CLI の JSON 結果・標準エラー出力を確認できます。CLI 内部のサーバー待機・変換・追跡の厳密な時間分離は行いません。ログには組織名、パス、メタデータ名が含まれるため、Git の管理対象から除外しています。

取得は `sf project retrieve start --json` で実行します。CLI のアニメーションや全ファイルの表を画面へ流さず、標準出力と標準エラー出力を別々に回収し、詳細はまとめてログへ保存します。取得中は最大毎秒の経過時間表示と不定進捗バーを使います。JSON は通常終了時に返るため、途中の正確な件数・パーセントは表示しません。これはローカルの出力・画面更新負荷を減らす変更で、Salesforce 側の処理時間短縮を保証するものではありません。

Memeta は取得ごとに `temp/` を削除する世代バックアップ用途のため、取得用の `sf` 子プロセスだけに `SF_DISABLE_SOURCE_MEMBER_POLLING=true` を渡します。これにより、取得後の SourceMember 追跡待機を省略します。この一時プロジェクトの追跡状態は同期しなくなりますが、取得後に削除するためMemetaでは使用しません。PC全体の環境変数や、他のSalesforceプロジェクトの設定を永続変更することはありません。

CLIの終了後は到着済みの出力を回収します。標準出力または標準エラー出力が閉じないまま1秒の猶予を超えた場合、取得物が途中である可能性を安全側で扱い、バックアップを作成せずエラーにします。この場合は確認用にtempを保持します。再実行・アプリ再起動時にはtempを清掃するため、先に残ったCLIプロセスの終了と計測ログを確認してください。

### 取得結果の見方

- **正常完了**: CLI の JSON で成功を確認し、警告なしでバックアップを保存しました。選択していない資材を含む「組織全体の完全性」を保証する意味ではありません。
- **警告あり完了**: 取得できた資材は保存しましたが、権限不足・未対応の言語などの警告があります。対象・理由をスクロール可能な完了画面、画面ログ、計測ログで確認してください。CLI 自体の通知（標準エラー出力）も警告に含めます。
- **取得対象0件**: CLI の取得処理は完了しましたが、今回の条件で取得されたファイルがありません。対象のメタデータが存在しない場合にも起こるため、0件だけを理由にエラー・警告とはしません。資材ファイルは保存せず、従来どおり比較履歴用の空の世代フォルダを残します。別途警告がある場合は「取得対象0件（警告あり）」として詳細を表示します。集計上は「取得対象0件」の環境数に含めます。
- **エラー**: 終了コードの異常、JSON の解析不良・未完了・失敗、資材変換の失敗などです。CLI の終了コードが 0 でも、取得成功を確認できなければバックアップを作成しません。

警告数ではなく、各結果になった**環境数**を完了画面に表示します。CLI が資材名を返さない警告は、名前を推測せず返された理由を表示します。

CLI は取得メッセージを `files` 内の `Failed` 項目にも変換します。全体が `Succeeded`・`success: true`・`done: true` であり、メッセージの変換形と件数が一致する `Failed` は警告として扱います。一致しない `Failed` はエラーのままです。理由が空の取得メッセージは「詳細不明の取得メッセージ: N件」とまとめ、元の JSON はログに残します。

### バックアップ差分表示

取得・保存後、同じ組織の直前の保存済みバックアップ（警告あり完了も含む）と自動比較します。保存先の世代名の日時順で選び、同秒の連番は数値順で扱います。失敗してバックアップが残らなかった実行、一時コピーの `.partial`、別組織の世代は比較対象にしません。初回は「比較対象なし」です。

- **追加**: 今回だけ存在する相対パス。
- **削除**: 前回だけ存在する相対パス。
- **変更**: 同じ相対パスでファイル内容が異なるもの。
- **変更なし**: 内容が同一のもの。更新日時だけの違いは無視します。

テキストもバイナリもバイト単位で比較します。改行コードだけの違いも変更、名前変更は削除＋追加となります。空フォルダや XML の意味・行単位の差分は対象外です。結果は完了画面に組織別の件数・ファイル一覧として表示し、当該実行の `data/<org>/logs/` に比較元・比較先とともに保存します。バックアップ内へ管理ファイルを追加しません。

これは**保存されたファイル同士の比較**です。package.xml の変更や権限不足などの取得警告でも増減するため、削除を Salesforce 上の削除と断定しないでください。比較に失敗・中止した場合も取得済みバックアップは残し、警告として通知します。比較処理は元ファイルを変更しません。比較中はバックアップを手動編集しないでください。

前回・今回の比較ファイル数も表示します。両方0件の場合は「比較するファイルがありません」、片方のみ0件の場合は全件が追加／削除になる理由を表示します。比較対象の選び方や差分の計算方法は変わりません。

## ローカルテスト

```bash
python -m unittest discover -s tests -v
```

Salesforce に接続せず、一時フォルダと模擬 CLI 結果を使って検証します。実 OS パイプの読み取りテストも含みます。実環境の取得時間と GUI の見た目は、別途起動して確認してください。

## 保存先と安全性

- 設定は `memeta_config.json`、manifest は `data/<org>/package.xml` に保存されます。
- 実設定と `data/` 全体（manifest・バックアップ・ログ）は Git 管理対象外です。公開リポジトリには含めません。
- Salesforce CLI の作業物は `temp/` のみを使用し、終了・中止・次回起動時にクリーンアップします。
- このツールが削除するのは `temp/` と設定から明示的に削除した組織エントリだけです。取得済みバックアップと Salesforce CLI の認証情報は削除しません。

## 注意

`sf org login web` はブラウザを開きます。OAuth のリダイレクトで使う 1717 番ポートに残ったプロセスがあれば、ログイン直前に終了を試みます。
